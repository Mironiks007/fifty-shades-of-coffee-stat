# Автотесты генераторов S2

Тесты запускают ячейки с генераторами из двух ноутбуков. Внутри тестов алгоритмы заново не реализуем: проверяем именно код, который сдаём. Долгие контрольные прогоны и построение графиков из ноутбуков при этом не запускаются. Для тестов используется локальный CSV.

| Что проверяем | Как проверяем |
|---|---|
| Обратное преобразование | Проверяем границы интервалов CDF и значения вне допустимого диапазона |
| Псевдонимы | Для маленьких таблиц перебираем все пары «ячейка, билет» и проверяем точные частоты, в том числе нулевую частоту |
| Отбор с отклонением | Задаём известную последовательность предложений и проверяем, что попытки после последнего принятия не засчитываются |
| Три эмпирических генератора | Проверяем общий профиль, Мексику и Гватемалу: по 30 000 результатов, допустимые уровни, сравнение CDF с частотами из CSV, а также размер, пустой запрос, одинаковый seed и ошибки ввода |
| Суперпозиция | Проверяем смеси 50/50 и 80/20, распределение влажности вместе с меткой страны, веса 0 и 1 и недопустимые веса |
| Округлённое бета-распределение | Сравниваем генерацию с аналитическим случаем Beta(2, 1) и отдельно с моделью, подогнанной в ноутбуке |

Для вероятностных проверок используем фиксированные начальные состояния генератора. Сравниваем максимальную разницу накопленных частот с границей sqrt(log(2/α)/(2n)) из [неравенства Дворецкого — Кифера — Вольфовица с константой Массара](https://doi.org/10.1214/aop/1176990746), где α = 0,000001 на одно сравнение. Это допуск для случайной выборки, а не требование совпасть с каждой ожидаемой частотой до последнего знака.

Автотесты отвечают на вопрос, правильно ли код генерирует из заданного закона. Поэтому тест бета-генератора может пройти, хотя само бета-распределение не подходит для описания наблюдений S1.

## Локальный запуск

Из корня архива или репозитория, Python 3.12:

```sh
python -m pip install -r requirements-autotests.txt
python -m unittest discover -s tests -v
```

Локальный результат для приложенных файлов: **10 тестов прошли**.

## Как добавить в репозиторий

Разместите файлы из архива в корне рабочей ветки. Если в репозитории уже есть тот же `coffee_ratings.csv`, повторно добавлять его не нужно. Для тестов нужны актуальные версии обоих ноутбуков из архива: `stat-lab1-s2.ipynb` и `stat-lab1-s2-bonus-alias.ipynb`.

Файл `.github/workflows/generator-tests.yml` должен попасть именно в каталог `.github/workflows/`. После отправки изменений проверка **Generator tests** запускается на push и в pull request. Результат виден во вкладке **Actions**.
